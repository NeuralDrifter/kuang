# Agent i18n — Remaining Work

**Goal:** finish bilingual (en-US / zh-CN) coverage in `packages/agent`. Labels
are already localized; the strings _inside_ them are not, so a zh-CN user sees
`需要批准: write_file(...)` followed by `Denied by the user`.

This is the last unmet requirement from the agent core. Everything else there
is done and verified: `vp check` 0 errors, 77/77 tests, live run clean.

---

## The one design rule

Not every string should be translated. Split them by **audience**:

| Audience                                            | Rule              | Why                                                                        |
| --------------------------------------------------- | ----------------- | -------------------------------------------------------------------------- |
| **User-visible** — anything reaching the renderer   | **Localize**      | The person reads it                                                        |
| **Model-facing** — `role: "tool"` message `content` | **Leave English** | The model reads it, and English is fine; translating adds risk for no gain |

Concretely, in `loop.ts` a refusal produces _two_ strings: a `tool_result.summary`
(user-visible → localize) and a tool message `content` (model-facing → English).
They are deliberately different. Do not collapse them.

## Plumbing

`fsTools(root)` and `shellTool(root, available, opts)` currently take no
language. Add it — either a parameter or an options field. `runTurn` already
receives `language` in its options, so `loop.ts` needs no new plumbing.

**Also fold in:** `localize` is copy-pasted in three files
(`core/tools/registry.ts`, `src/index.ts`, `ui/plain.ts`). Move it to a single
`packages/agent/src/core/i18n.ts` and import from there. `ui/` may import
`core/`; **`core/` must never import `ui/`** — that rule is load-bearing, it is
what makes the agent testable without a terminal.

Separately: `packages/agent/package.json` declares `bailian-cli-runtime` but
imports it nowhere. Either use its `createTranslator` for the above, or drop
the dependency.

## Pattern to follow

Use the repo's existing `LocalizedText` shape — `{ "en-US": ..., "zh-CN": ... }`
— the same one command metadata uses. For interpolated strings, a function
returning `LocalizedText` works fine:

```ts
const MSG = {
  wrote: (bytes: number, path: string): LocalizedText => ({
    "en-US": `Wrote ${bytes} bytes to ${path}`,
    "zh-CN": `已写入 ${bytes} 字节到 ${path}`,
  }),
};
```

Use full-width Chinese punctuation — `，` `。` `：` — not ASCII. 123 of 144
source files in this repo already do.

## Out of scope

Do not touch the approval logic, the tool implementations' behaviour, or the
turn loop's control flow. This is a string-and-plumbing change only. Two
security items are deliberately deferred to a later plan and must not be
half-started here:

1. A denylist of commands that may never be generalised into an approval rule
   (`rm`, `dd`, `mkfs`, …). **Must land in the same change as approvals
   persistence, never after** — today a rule from `rm -f build/tmp.txt` permits
   `rm -f -r /`, contained only because approvals are in-memory per session.
2. `realpath` containment — `read_file` is auto-tier and follows symlinks, so a
   hostile repo can exfiltrate silently.
